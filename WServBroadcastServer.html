WServBroadcastServer

WServBroadcastServer

new WServBroadcastServer(instWConverServer, optopt) → {Object}

Description:

  • 伺服器端之資料控制與廣播器

    身分驗證責任：本套件不驗證身分(token)，只於輪詢([sys:polling])之任何副作用之前呼叫使用端注入之opt.verifyPolling；未注入時任何能通過通訊層(例如WConverhpServer之verifyConn)者皆可輪詢，即取得其後之全部廣播(含部署方broadcast之內容)並建立在線身分與佇列，未注入時之預設為放行。使用端須自行完整驗證——verifyConn驗連線之token(含本系統使用者存在、啟用、部署方授權)；verifyPolling驗輪詢之身分(須同等完整，反查執行身分即驗證身分，不可只解碼或只查id，並自行決定空身分是否放行，另須檢查clientId歸屬該身分)；應用端自行註冊之其他execute監聽(各函數)與資料授權各自把關，含函數層級之角色或成員檢查。

Name Type Attributes Default Description
verifyPolling function <optional>
 null

輸入輪詢之身分驗證鉤子函數(sync或async皆可)，由使用端注入，預設null(不驗證，行為同未提供本選項時：本套件不驗證身分，任何能通過通訊層者皆可輪詢，風險見上方「身分驗證責任」)。給予函數時，每次[sys:polling]於任何副作用(建立佇列、建立或刷新在線身分、取出訊息、發出clientEnter等事件)之前呼叫，傳入該次輪詢之輸入物件之複本(含clientId、前端opt.getToken放於固定鍵__sysToken__之token，及使用端自行放入之其他欄位)；回傳(或resolve，thenable亦以Promise規則吸收)嚴格true才放行，其他值(含看似為真之值，例如1、'user-1'、{})、拋錯或reject一律拒絕：以固定訊息'[sys:polling] permission denied'拒絕該次輪詢(訊息不含拒絕原因，原因只經error事件供稽核)，不建立或刷新任何狀態(已在線者之佇列亦不取出)，並發error事件(內容見回傳之說明)。放行後交給使用端監聽之clientEnter、clientLeave之data已剝除固定鍵__sysToken__，使token不進入事件資料(未提供verifyPolling時同樣剝除：輸入含自有鍵__sysToken__者取副本去鍵後交付，不改動呼叫端傳入之原物件；不含該鍵者行為同現行，輸入原物件交付)；提供verifyPolling時，clientId、傳給鉤子之輸入與交給使用端之data皆取自輪詢到達當下之同一份快照(深複製)，驗證期間原輸入物件被他人改動(例如同一事件物件上其他execute監聽共用同一輸入)不影響檢查之值與使用之值；提供verifyPolling時，輪詢之回覆(含拒絕)於鉤子結算後非同步送出(未提供時同現行，同步回覆)，故同一事件物件上於本套件之後註冊、且對[sys:polling]同步回應之監聽(例如對所有函數名皆回應invalid token之資料通道)會先結算該請求而使輪詢失敗，此類監聽須略過sys:polling。鉤子須自行驗證token是否有效、使用者是否存在且啟用、部署方是否授權，並檢查clientId歸屬該身分(clientId由前端自訂，須唯一，否則與他人互相取走訊息)。clientId不是非空字串者先於鉤子被拒絕([sys:polling] invalid clientId)，不呼叫鉤子；本套件不內建鉤子逾時，鉤子不結算時該次輪詢懸置至前端逾時，須由鉤子自行處理逾時；clearBroadcast時在途之驗證於其結算後不建立任何狀態、不發任何事件、不回應。給了非函數(undefined與null除外)時建構拋錯(opt.verifyPolling is not a function)，不靜默放行
onTrace function <optional>
 null

輸入觀察回調函數，格式為(e)=>{}，預設null(未給或非函數時不組事件物件，行為、時序與效能同未提供)，供測試與診斷以事件(而非等待毫秒)同步。於內部事件發生當下同步呼叫，e為凍結之事件物件{ type, ... }(欄位皆為原始值)；回調不帶接收者呼叫，其同步拋錯與回傳之rejection皆忽略，不影響廣播與在線偵測，回傳值不使用。type有：alive(在線偵測wsemi之alive所轉交之事件，evType為其type：'enter'或'leave'〔key為clientId，now為該事件後之在線數，早於本套件clientEnter或clientLeave之排定〕、'tick'〔每次偵測佇列，size為偵測前之數量〕、'stop'〔佇列已空而停止偵測〕，在線逾時固定10秒、偵測間隔固定50毫秒)、prune(修剪佇列之計時器〔每1秒〕每次觸發，queues為修剪後之佇列數，removed為本次移除之佇列數)、emit(本套件事件已排定於1ms後派發，name為事件名，final為是否為停止時之補發)、deliver(事件已派發而監聽器皆已呼叫完，name為事件名，final同上，ok為監聽器是否皆未拋錯)、report(本套件改以error事件或console.error通報：src為'listener'〔監聽器拋錯，name為其事件名〕或'error'〔本套件自發之error於無error監聽者〕，msg為其描述字串，via為'event'或'console')、stop(clearBroadcast首次呼叫完成，final為已排定補發clientLeave之客戶端數)。停止後除停止當下已在進行之那次派發與補發事件之deliver、report外不再通知；停止前已排定而於停止後被閘門丟棄之事件不通知
Returns:

回傳事件物件，可監聽clientEnter、clientLeave、clientChange、error事件，並保留instWConverServer原有之execute、upload、download、handler事件；另掛載broadcast、getClients、getMessages、clearBroadcast函數。本套件只處理函數名為[sys:polling]之execute，其他函數名須由應用端自行註冊execute監聽並回應，否則該請求懸置至前端逾時；本套件之execute監聽須先於「對所有函數名皆回應」之監聽註冊，否則輪詢由該監聽回應。輪詢之clientId須為非空字串，任意字串(含__proto__、constructor、含.或[]者)皆為一般識別，回覆一律為陣列；clientId不是非空字串者拒絕該次輪詢([sys:polling] invalid clientId)，不發事件、不建立在線身分。clientEnter與clientLeave帶(clientId, data)，clientEnter之data為該客戶端首次輪詢時所送之輸入物件，clientLeave之data為其最後一次輪詢時所送者(兩者皆已剝除token鍵__sysToken__，不論是否提供opt.verifyPolling)；clientChange帶當前存活客戶端數量(含剛輪詢而尚未發出clientEnter者)。broadcast以呼叫當下之值(複製)廣播給當前在線之客戶端，data須可序列化(同通訊服務之規則)，否則同批廣播於輪詢時遺失。在線逾時固定10秒，傳遞為至多一次：客戶端兩次成功輪詢之間隔達10秒時視為離線並丟棄其未取走之廣播，回覆送不到(例如不可序列化之data、傳輸失敗)時同批之廣播遺失。偵測到客戶端離線(在線逾時)時，先刪除該clientId之佇列與其未取走之廣播，才發出clientLeave與clientChange(事件於其後約1ms脫勾派發)：故clientLeave發出時離線前之廣播已不在任何佇列(getMessages已無該離線前之佇列)，其後(含於clientLeave監聽內)以同一clientId輪詢者取得新的空佇列，取不到離線前之遺留廣播，離線後、重新輪詢前之廣播亦不進入舊佇列；使用端因此可於clientLeave解除clientId與身分之綁定，不致使他人其後以同一clientId取得離線者遺留之廣播。若同一clientId於偵測到離線後、clientLeave派發前(約1ms內)已重新輪詢，則getMessages所見為該次重新進入之新佇列(僅含離線後之廣播)。注入opt.verifyPolling時，驗證在途而跨過離線者於放行時才取用佇列(取得新的空佇列)，鉤子須於在線逾時內結算，否則其放行結果可能於同一clientId已被他人重新綁定後才生效(本套件不內建鉤子逾時)。clearBroadcast停止時補發之clientLeave，發出時佇列同樣已清空(停止為終態，其後不再回應輪詢)。clearBroadcast為停止並釋放：清除本套件之計時器與在線偵測(行程可立即結束)、移除所掛之execute監聽(其後不再回應輪詢，含於同一次execute派發中先註冊之監聽內停止者；停止後之輪詢由同一事件物件上其他execute監聽回應，無其他監聽時由通訊服務立即拒絕，另有不回應[sys:polling]之監聽時懸置至前端逾時)，並對已送達clientEnter而尚未送達clientLeave之客戶端補發clientLeave與clientChange使進出成對；停止前已排定而尚未送達之事件不再派發，補發之後不再派發本套件之事件，惟呼叫當下那次派發之其餘監聽器仍會收到；停止後之監聽器拋錯(含補發事件之監聽器)以console.error輸出；停止後broadcast無作用、getClients回傳[]、getMessages回傳{}，可重複呼叫。getMessages回傳以clientId為鍵之一般物件(複製)。error事件之內容一律為{ msg, err }，msg為描述字串、err為原因(原始錯誤或出錯之值)：輪詢處理失敗為{ msg: '[sys:polling] error', err }；注入opt.verifyPolling時，鉤子回傳非true而拒絕為{ msg: '[sys:polling] permission denied', err }(err為鉤子之回傳值)，鉤子本身拋錯或reject而拒絕為{ msg: '[sys:polling] verifyPolling error', err }(err為所拋之值)，每次被拒絕各發一則(遠端大量輪詢時，error事件之數量同被拒絕之輪詢數)；本套件之error於派發當下無error監聽者時改以console.error輸出；監聽器之同步拋錯不會使行程崩潰，改以error事件通知，內容為{ msg: 'listener of event[x] error', err }(x為事件名、err為所拋之值)，無error監聽者時改以console.error輸出；error監聽器自身拋錯亦以console.error輸出。惟依EventEmitter規範，同一次派發中先拋錯之監聽器會中止該次派發，其後之監聽器不再被呼叫；async監聽器之reject不被攔截，須由監聽器自行處理
