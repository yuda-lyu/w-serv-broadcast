Example
import WConverhpClient from 'w-converhp/src/WConverhpClient.mjs'
import WServBroadcastClient from './src/WServBroadcastClient.mjs'

let opt = {
    url: 'http://localhost:8080',
    apiName: 'api',
}

//instWConverClient
let instWConverClient = new WConverhpClient(opt)

//instWConverClient
instWConverClient = new WServBroadcastClient(instWConverClient)

instWConverClient.on('broadcast', function(data) {
    console.log(`broadcast`, data)
})
instWConverClient.on('openOnce', function() {
    console.log(`openOnce`)
})
instWConverClient.on('open', function() {
    console.log(`open`)
})
instWConverClient.on('error', function(err) {
    console.log(`error`, err)
})

Name Type Attributes Default Description
instWConverClient Object

輸入通訊服務實體物件，須為具emit、on與execute函數之eventemitter3事件物件(例如wsemi之evem所建立者)，可使用例如WConverhpClient等建立；未給、非事件物件(無emit或on)或無execute函數時，因無法輪詢而於建構時拋錯。通訊物件上之clientId(非空字串)可自訂本前端之識別，須唯一，否則與他人互相取走訊息，未給則隨機產生。同一通訊物件只能建立一個本前端，重建前須先呼叫clearBroadcast。本套件以execute('[sys:polling]', { clientId }, cbProgress, { signal })輪詢，第4參數之signal供停止時中止在途之輪詢(見clearBroadcast)，包裝通訊物件之execute者須原樣轉交第4參數；通訊物件須於每次呼叫結束移除其掛於該signal之監聽，且該監聽不得拋錯(於Node以uncaughtException結束行程)，WConverhpClient 2.1.8以上皆符合；須執行環境內建AbortController(Chrome 66、Firefox 57、Safari 11.1、Edge 16、Node 14.17以上)，否則建構時拋錯

Returns:

回傳事件物件，可監聽openOnce、open、broadcast、error事件，另掛載clearBroadcast函數供停止輪詢。輪詢回應須為陣列且元素皆為具字串mode之物件(本套件伺服端之回覆形狀)，否則整包視為輪詢失敗(err為回應原值)且不視為已連線；只派發mode為broadcast之訊息，其他mode略過。openOnce於第一次收到合格回應時發出一次；open於由未連線轉為連線時發出(首次或失敗後恢復)；broadcast帶伺服端所廣播之data。每輪輪詢失敗(含通訊物件execute之reject、同步拋錯、未回傳Promise，及回應不合協定)發一則{ msg: '[sys:polling] error', err }並轉為未連線，恢復時再發open，不另提供斷線事件；同一事件物件上另有通訊物件自身之error(例如WConverhpClient每次嘗試失敗之訊息)，不代表該輪失敗。傳遞為至多一次：兩次成功輪詢之間隔達伺服端在線逾時、或伺服端之回覆送不到時，期間或同批之廣播遺失。clearBroadcast為停止並釋放，可重複呼叫，其後不再派發本套件之事件(含停止前已排定、停止時在途之輪詢結果)，並中止停止時在途之輪詢請求：通訊物件支援execute之opt.signal者(例如WConverhpClient 2.1.8以上)，該請求不再重試、不再發出其error與重試訊息、不再呼叫getToken，停止後本套件除已排定之派發計時器(1ms內觸發而不派發)外不再持有計時器與在途之請求(行程可立即結束)；伺服端已開始處理之該次輪詢照常完成，其取走之廣播隨之遺失(同傳遞為至多一次)；通訊物件不支援者(例如WConverhpClient 2.1.7以前)，該請求照常完成或重試並發出其自身之error，惟其結果不派發。中止只及於本套件之輪詢請求，同一事件物件上之其他呼叫不受影響；於監聽器內呼叫clearBroadcast時，該次派發(含通訊物件之error事件)之其餘監聽器仍會收到該事件；停止後之監聽器拋錯以console.error輸出。error事件之內容一律為{ msg, err }，msg為描述字串、err為原因(原始錯誤或出錯之值)；本套件之error於派發當下無error監聽者時改以console.error輸出；監聽器之同步拋錯不會使行程崩潰，改以error事件通知，內容為{ msg: 'listener of event[x] error', err }(x為事件名、err為所拋之值)，無error監聽者時改以console.error輸出；error監聽器自身拋錯亦以console.error輸出。惟依EventEmitter規範，同一次派發中先拋錯之監聽器會中止該次派發，其後之監聽器不再被呼叫；async監聽器之reject不被攔截，須由監聽器自行處理
