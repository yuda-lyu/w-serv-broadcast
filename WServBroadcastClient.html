WServBroadcastClient

WServBroadcastClient

new WServBroadcastClient(instWConverClient, optopt) → {Object}

Description:

  • 瀏覽器端之資料控制與廣播器

    身分驗證責任：本套件不驗證身分(token)，只依opt.getToken於每次輪詢之輸入帶使用端提供之token；驗證一律由伺服端使用端注入之WServBroadcastServer之opt.verifyPolling負責，未提供getToken時輪詢不帶token，伺服端未注入verifyPolling時任何能通過通訊層者皆可輪詢(預設為放行)。使用端須自行完整驗證，包含連線之token、輪詢之身分與各函數之授權。

Example
import WConverhpClient from 'w-converhp/src/WConverhpClient.mjs'
import WServBroadcastClient from './src/WServBroadcastClient.mjs'

let opt = {
    url: 'http://localhost:8080',
    apiName: 'api',
}

//instWConverClient
let instWConverClient = new WConverhpClient(opt)

//instWConverClient, 伺服端注入verifyPolling驗證輪詢之身分時, 以getToken提供token:
//instWConverClient = new WServBroadcastClient(instWConverClient, { getToken: () => localStorage.getItem('token') })
instWConverClient = new WServBroadcastClient(instWConverClient)

instWConverClient.on('broadcast', function(data) {
    console.log(`broadcast`, data)
})
instWConverClient.on('openOnce', function() {
    console.log(`openOnce`)
})
instWConverClient.on('open', function() {
    console.log(`open`)
})
instWConverClient.on('error', function(err) {
    console.log(`error`, err)
})

instWConverClient Object

輸入通訊服務實體物件，須為具emit、on與execute函數之eventemitter3事件物件(例如wsemi之evem所建立者)，可使用例如WConverhpClient等建立；未給、非事件物件(無emit或on)或無execute函數時，因無法輪詢而於建構時拋錯。通訊物件上之clientId(非空字串)可自訂本前端之識別，須唯一，否則與他人互相取走訊息，未給則隨機產生。同一通訊物件只能建立一個本前端，重建前須先呼叫clearBroadcast。本套件以execute('[sys:polling]', { clientId }, cbProgress, { signal })輪詢，第4參數之signal供停止時中止在途之輪詢(見clearBroadcast)，包裝通訊物件之execute者須原樣轉交第4參數；通訊物件須於每次呼叫結束移除其掛於該signal之監聽，且該監聽不得拋錯(於Node以uncaughtException結束行程)，WConverhpClient 2.1.8以上皆符合；須執行環境內建AbortController(Chrome 66、Firefox 57、Safari 11.1、Edge 16、Node 14.17以上)，否則建構時拋錯

timePolling Integer <optional>

輸入每次輪詢間隔時間正整數，單位為毫秒ms，預設2000，0與無效值取預設，超過計時器上限2147483647者夾至上限；須明顯小於伺服端之在線逾時(固定10秒)，否則伺服端會判定斷線並丟棄期間之廣播
getToken function <optional>
 null

輸入取得token之函數(sync或async皆可)，由使用端提供，預設null(輪詢輸入不帶token，恰為{ clientId }，行為同未提供本選項時)。給予函數時，每輪輪詢前呼叫(不帶參數)，將其回傳之字串放於輪詢輸入之固定鍵__sysToken__(非字串取空字串)，供伺服端opt.verifyPolling驗證，伺服端交使用端監聽(clientEnter等)之前剝除此鍵(不論是否提供verifyPolling，放行後才交付)；每輪重新取得，故token可輪替。getToken拋錯或reject時該輪不發出輪詢，以{ msg: '[sys:polling] error', err }通知並轉為未連線，下一輪重新取得；取得token期間呼叫clearBroadcast者，其後不發出輪詢、不派發事件(本套件不中止使用端之getToken，惟其結果被丟棄)。token隨每次輪詢明文送出，傳輸安全(例如HTTPS)由使用端與通訊層負責。給了非函數(undefined與null除外)時建構拋錯(opt.getToken is not a function)
onTrace function <optional>
 null

輸入觀察回調函數，格式為(e)=>{}，預設null(未給或非函數時不組事件物件，行為、時序與效能同未提供)，供測試與診斷以事件(而非等待毫秒)同步。於內部事件發生當下同步呼叫，e為凍結之事件物件{ type, ... }(欄位皆為原始值)；回調不帶接收者呼叫，其同步拋錯與回傳之rejection皆忽略，不影響輪詢與結果，回傳值不使用。type有：start(建構完成起輪詢，ms為輪詢間隔)、tick(輪詢計時器每次觸發，n為已開始之輪數，skipped為前一輪尚在途而本次略過〔不重入〕)、request(對通訊物件發出第n輪之輪詢，token為輸入是否帶token〔getToken〕；getToken拋錯或reject之該輪不發出)、result(第n輪結果，reason為'ok'〔合格回應，msgs為回應之訊息數〕、'invalid'〔回應不合協定〕或'error'〔execute之reject、同步拋錯、未回傳Promise、getToken拋錯或reject〕，ok為reason是否為'ok'；皆早於該輪對應事件之派發)、emit(本套件事件已排定於1ms後派發，name為事件名)、deliver(事件已派發而監聽器皆已呼叫完，name為事件名，ok為監聽器是否皆未拋錯，final恆為false)、report(本套件改以error事件或診斷輸出〔console.error或opt.funLog〕通報：src為'listener'〔監聽器拋錯，name為其事件名；監聽器拋錯而error監聽器亦拋錯時，先通知後者〔name為'error'、via為'console'〕再通知原事件之通報〔via為'event'〕〕或'error'〔本套件自發之error於無error監聽者〕，msg為其描述字串，via為'event'或'console')、stop(clearBroadcast首次呼叫完成，inflight為停止時是否有在途之輪詢)。停止後除停止當下已在進行之那次派發之deliver與report外不再通知；停止前已排定而於停止後被閘門丟棄之事件不通知
logDetail Boolean <optional>
 false

輸入診斷輸出是否還原為遮罩後之細節(供除錯)，預設false。本套件之診斷輸出(error事件無監聽者時之error、停止後或error監聽器之監聽器拋錯)一律經wsemi之getDiag：預設false時只輸出固定標籤與安全摘要{ src, name, errType, errCode }，不含值(err可能含token或使用者識別)；true時console輸出遮罩後之細節(憑證樣式與getToken所得之token〔最近64個〕皆遮罩為***)。有給(非undefined、null)但非布林值時建構即同步拋錯(invalid opt.logDetail)，先於任何資源之配置
funLog function <optional>
 null

輸入診斷輸出函數，格式為(label, safe, detail)=>{}，預設null。給予時診斷輸出只交給它(不寫console，logDetail不作用)，detail為遮罩後之細節；其同步拋錯與回傳之rejection皆吞下，不影響本套件；帶屬性noDetail===true者只以(label, safe)呼叫。有給(非undefined、null)但非函數時建構即同步拋錯(invalid opt.funLog)
Returns:

回傳事件物件，可監聽openOnce、open、broadcast、error事件，另掛載clearBroadcast函數供停止輪詢。輪詢回應須為陣列且元素皆為具字串mode之物件(本套件伺服端之回覆形狀)，否則整包視為輪詢失敗(err為回應原值)且不視為已連線；只派發mode為broadcast之訊息，其他mode略過。openOnce於第一次收到合格回應時發出一次；open於由未連線轉為連線時發出(首次或失敗後恢復)；broadcast帶伺服端所廣播之data。每輪輪詢失敗(含通訊物件execute之reject〔例如被伺服端opt.verifyPolling以固定訊息[sys:polling] permission denied拒絕〕、同步拋錯、未回傳Promise、getToken拋錯或reject，及回應不合協定)發一則{ msg: '[sys:polling] error', err }並轉為未連線，恢復時再發open，不另提供斷線事件；同一事件物件上另有通訊物件自身之error(例如WConverhpClient每次嘗試失敗之訊息)，不代表該輪失敗。傳遞為至多一次：兩次成功輪詢之間隔達伺服端在線逾時、或伺服端之回覆送不到時，期間或同批之廣播遺失。clearBroadcast為停止並釋放，可重複呼叫，其後不再派發本套件之事件(含停止前已排定、停止時在途之輪詢結果)，並中止停止時在途之輪詢請求：通訊物件支援execute之opt.signal者(例如WConverhpClient 2.1.8以上)，該請求不再重試、不再發出其error與重試訊息、不再呼叫getToken，停止後本套件除已排定之派發計時器(1ms內觸發而不派發)外不再持有計時器與在途之請求(行程可立即結束)；伺服端已開始處理之該次輪詢照常完成，其取走之廣播隨之遺失(同傳遞為至多一次)；通訊物件不支援者(例如WConverhpClient 2.1.7以前)，該請求照常完成或重試並發出其自身之error，惟其結果不派發。中止只及於本套件之輪詢請求，同一事件物件上之其他呼叫不受影響；於監聽器內呼叫clearBroadcast時，該次派發(含通訊物件之error事件)之其餘監聽器仍會收到該事件；停止後之監聽器拋錯以診斷輸出輸出(見opt.logDetail、opt.funLog)。error事件之內容一律為{ msg, err }，msg為描述字串、err為原因(原始錯誤或出錯之值)；本套件之error於派發當下無error監聽者時改以診斷輸出輸出(預設為console.error只輸出固定標籤與安全摘要{ src, errType, errCode }，不含err之值——其可能含token或使用者識別，例如opt.getToken所拋之值或不合協定之回應原值；opt.logDetail為true時輸出遮罩後之細節，opt.funLog給予時只交給它；error事件之內容仍為原值{ msg, err }、不遮罩，使用端自行輸出時須自行處理)；監聽器之同步拋錯不會使行程崩潰，改以error事件通知，內容為{ msg: 'listener of event[x] error', err }(x為事件名、err為所拋之值)；無error監聽者、停止後、或拋錯者本身為error監聽器時，該拋錯改以診斷輸出輸出(label為[w-serv-broadcast] listener of event[x] error，摘要含src為'listener'與name為事件名，不含所拋之值)，監聽器拋錯而error監聽器亦拋錯時，後者亦以診斷輸出輸出(x為error)。惟依EventEmitter規範，同一次派發中先拋錯之監聽器會中止該次派發，其後之監聽器不再被呼叫；async監聽器之reject不被攔截，須由監聽器自行處理
